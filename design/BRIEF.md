# Profile design brief

**Repository:** `YashModi1804/YashModi1804`. The deliverable is Yash Modi's GitHub
profile README and its artwork, content, and activity assets.

## Creative goal

Create an original personal profile with smooth, attention-holding animation.
The owner chose a **dark cinematic palette with warm accents** and explicitly
requested letters built from particles that break apart and reform. Earlier
technical checks are not evidence of creative approval.

Keep continuity: a sculptural Möbius ribbon forms the **O in MODI**. Choreograph
particle disassembly, controlled flow, and reassembly rather than random glitches.
Target **25 fps** with readable holds at both ends of a seamless loop. The static
poster shows the fully formed name. Brief disassembly is intentional; native
Markdown always preserves Yash's name. Use carbon, ivory, and warm bronze, with
subordinate supporting motion. Keep particles within the canvas, avoid flicker,
and verify the formed name remains legible on mobile.

## Content that must survive

Preserve Yash Modi, India, **Associate Engineer at Oracle**, all three learning
interests, four conversation topics, both contact destinations, all 14 tools,
the exact personal quote, and the existing visitor counter identity. Learning
must remain learning, not an expertise claim. Retain access to the original
statistics, streak, and language views alongside the accurately scoped local
activity ledger. Add no invented credentials, employer responsibilities, or
performance claims. Essential facts remain readable as native Markdown.

Keep `archive/README.before-redesign.md` unchanged and retain the restoration
tag. The maintenance guide documents rollback and regeneration.

## Roles and release gates

These are responsibilities for this task, not permanently running agents:

- **PM:** reconcile preferences, scope, content preservation, and acceptance.
- **Art director:** author the composition and inspect motion, themes, and poses.
- **Content:** audit factual copy, links, accessibility text, and preservation.
- **Metrics:** maintain sourced calculations, scope labels, and update workflow.
- **Release lead:** integrate changes and verify the actual GitHub presentation.

GitHub renders Markdown and supported images; do not rely on embedded scripts,
custom page CSS, or unsupported animation controls. Supply still artwork and
reduced-motion sources, then verify what GitHub actually preserves.

Before release: inspect intermediate poses and the loop seam; verify decoded
frame timing; check light/dark rendering, reduced-motion behavior, image loading,
and mobile readability; audit all preserved content and the archive hash; run
metric tests and verify the workflow. Report measured results and remaining
limitations rather than assuming the local preview proves the live result.
