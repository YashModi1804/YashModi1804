# Profile design brief

**Repository:** `YashModi1804/YashModi1804`. Deliver a coherent GitHub profile,
not just an animated name: who Yash is, what he builds, and inspectable proof.

## Current direction

The owner chose dark cinematic styling with warm accents and likes continuity.
The previous giant name/bronze object and plain body did not communicate enough
engineering substance. Identity artwork must support the work, not dominate it.
Earlier technical checks are not creative approval.

Use a compact particle wordmark with every letter participating; no sculpture.
The letters must visibly disperse into a genuine scattered cloud: no readable
letter silhouette remains at peak dispersion. Choreograph breakup, flow, and
accurate reassembly; avoid random glitches and flicker. Target **25 fps**, bounded
particles, readable end holds, and a seamless loop. The static poster shows the
complete name. Native identity text remains available during disassembly.

## Narrative and evidence

Lead with **Associate Engineer at Oracle · India**, then a grounded description
of full-stack software and AI integrations. Show selected work before decorative
activity statistics. Folio is the flagship: an actual labeled demo screenshot,
clear problem/behavior, source and demo links, and three inspectable decisions
(Decimal verification, persisted jobs, preserved review history).

A supporting scholarship workflow may illustrate React/Express/MongoDB work,
using only source-verified behavior. Do not claim institutional adoption, sole
authorship, security certification, employer duties, or business outcomes.
See `content-inventory.md` for exact evidence and approved descriptions.

Provide a visual toolkit with named logos and readable grouping. Preserve all
14 original tools; label additional technologies as a specific project's stack,
not implied expertise. Keep meaningful facts and links in native Markdown.
Preserve the learning interests, conversation topics, contacts, exact quote,
visitor counter, original metric links, and untouched archived README fallback.

## Roles and release gates

Task roles, not permanently running agents: PM owns scope/evidence; art owns
composition/motion; content owns factual preservation; metrics owns calculations;
the release lead integrates and verifies the live result.

GitHub supports Markdown and images, not a custom website runtime. Verify live
image loading, reduced-motion/static fallbacks, both viewing themes and mobile
readability. Inspect the fully scattered cloud, intermediate poses, reassembly,
loop seam, and decoded frame timing. Confirm project visuals match actual work
and fixture labels remain visible. Audit facts, links, toolkit, archive hash,
metrics tests, and update workflow before publishing; report measured results.
